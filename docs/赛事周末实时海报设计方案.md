# 赛事周末「实时赛程海报」设计方案

> 状态：**已实现**（2026-08-23）。目标：让周末赛事的 `f1dash.py` 海报在正赛前展示本周末已跑出的关键赛果，
> 而不仅是"还有多久开赛"。本文基于 2026 赛季 Jolpica F1 公开接口实测数据给出结论。

## 1. 目标

当前赛事海报（距下一场正赛开赛 `< 3 天` 触发）只有一张静态版式：大号赛道轮廓 + 比赛名 +
大字倒计时 + 比赛日/进度。整个周末它只回答"还有多久开赛"，不回答"这个周末已经跑出什么了"。

优化目标：海报在正赛前**渐进地**补充本周末已结束赛程的结果——
- 排位赛结束后（Saturday）→ 展示**排位赛结果**（决定正赛发车顺位，最贴近正赛）
- 冲刺赛结束后（冲刺周末 Saturday）→ 展示**冲刺赛结果**
- （冲刺排位赛结果按用户决策**不展示**，见 §3）

## 2. 现状梳理

`kindle/f1dash.py` 相关逻辑：

- `race_poster_active(data)`：`next_race` 开赛时间 - now <= `RACE_POSTER_WINDOW`(3 天) → 切海报
- `_draw_poster(d, data, font, text, centered)`：反色海报版式
  - 标题栏 y0-52（赛车 + F1 + ROUND N）
  - 海报区 y64-540：`draw_track_fit()` 大号赛道轮廓 + 比赛名 + 地点·国家 + 大字倒计时
  - 分隔线 y566 + 比赛日·北京时间 + 赛季进度 y606-656
  - 页脚 y760 `Last update`
- `get_dashboard_data()`：拉 current.json（唯一主获取）+ 车手榜 + 车队榜 + 上场比赛结果（各容错）

`data["next_race"]` 直接保留 `current.json` 里的原始 race 对象，因此**已带完整会话时间表**：
`Qualifying` / `Sprint` / `SprintQualifying` / `FirstPractice`…（均含 `date`+`time`，UTC）。
这正是判断"某会话是否已结束"的依据，无需额外请求。

## 3. 数据源与关键约束（Jolpica 实测）

2026 赛季冲刺赛在 R2/4/5/9/12/17。以 R2 中国站为例实测：

| 你要的信息 | Jolpica 端点 | 返回结构 | 可得性 |
|---|---|---|---|
| 排位赛结果 | `season/{round}/qualifying.json` | `QualifyingResults`（`position`/`Driver`/`Q1`/`Q2`/`Q3`） | ✅ 每站都有 |
| 冲刺赛结果 | `season/{round}/sprint.json` | `SprintResults`（`position`/`positionText`/`Driver`/`Time`/`status`/`grid`） | ✅ 仅冲刺站 |
| 冲刺赛排位赛结果 | `season/{round}/sprintqualifying.json` | — | ❌ 返回 HTTP 400，接口不提供 |

**关键测试**：R2 的冲刺赛发车杆位是 Russell（`grid=1`），而 `qualifying.json` 的杆位是 Antonelli
（`Q3 1:32.064`）。两者不同 → **`qualifying.json` 返回的是周六的"正赛排位赛"，而不是周五的
"冲刺排位赛"**。Jolpica/Ergast 没有独立冲刺排位赛结果端点。

> **用户决策**：冲刺排位赛结果**不展示**。海报在冲刺周末只展示 **排位赛结果** 与 **冲刺赛结果**
> 两块；普通周末只展示 **排位赛结果** 一块。（若要冲刺排位可后续另寻数据源，本方案不做。）

## 4. 触发逻辑（渐进式，按"会话已结束"）

识别哪些会话已有结果，靠会话时间表（`next_race` 自带）+ `now` 比较，不靠猜：

```
会话顺序（从 race 对象读取）：
   SprintQualifying(仅冲刺站) -> Sprint(仅冲刺站) -> Qualifying -> Race(正赛, time)
判据：session.date + session.time(UTC) -> epoch；若 <= now，则该会话已结束
```

海报会随周末推进**自动累积**结果块，且**只拉取已结束会话**的数据，避免白请求：

- 普通周末：周六排位赛结束后 → 出现 `QUALIFYING` 块
- 冲刺周末：周六冲刺赛结束后 → 出现 `SPRINT` 块（若排位未结束，先只出冲刺块）；
  周六正赛排位赛结束后 → 追加 `QUALIFYING` 块
- 正赛开赛：进入 `RACE LIVE`，各结果块保留；赛后转回下一场仪表盘（现有逻辑）

## 5. 海报版式设计（"有结果"状态）

保留"赛道轮廓为海报主角"的辨识度，但把结果块做成海报主体。推荐版式（600×800 设计网格）：

```
┌──────────────────────────────┐ y0-52   反色标题栏: 赛车 + F1 + ROUND 12
│        ↝ 赛道轮廓(白线)        │ y56-186 反色主角:大号赛道轮廓(略缩小)
│      DUTCH GRAND PRIX         │ y~198   比赛名(自动缩字)
│   Zandvoort · Netherlands      │ y~224   地点·国家
│      in 1d 04h               │ y~250   大字倒计时(记分牌式)
├──────────────────────────────┤ y~272   细分隔线
│   QUALIFYING                │ y286    结果块标题(反色)
│   1  Antonelli  1:32.064     │
│   2  Russell    +0.222       │  Top5 × 30px
│   3  Hamilton   +0.351       │
│   ...                        │
│   SPRINT RACE               │ ✓ 结果块标题(仅冲刺周末)
│   1  Russell   33:38.998     │
│   2  Leclerc   +2.1s         │  Top5 × 30px
│   ...                        │
├──────────────────────────────┤
│   SUNDAY 21:00 · Season 12/23 │  比赛日·北京时间 + 赛季进度(正色)
├──────────────────────────────┤ y760    Last update
```

要点：

- **块顺序：正赛相关度优先**（用户已确认）→ 排位赛在前，冲刺赛在后（即使冲刺赛更早结束）。
  普通周末只有 `QUALIFYING` 一块；冲刺周末先冲刺后追加排位。
- **没有会话结束时**：完全退回现有"大海报"版式（大赛道 + 大字倒计时）。
- **每块 Top 5**（用户已确认）：`pos | name | time/gap`，复用榜单渲染思路。
  - 排位：显示该车最快单圈（取 `Q3`，否则 `Q2`，否则 `Q1`）
  - 冲刺：显示完赛总时长/差距（`Time`），退赛者取 `status`（同 `fmt_results` 逻辑）
- 赛道名/倒计时沿用现有 `fit()` 动态缩字；赛道轮廓用 `draw_track_fit()` 装入缩小后的 box。

## 6. 实施改动清单

| 位置 | 改动 |
|---|---|
| `get_dashboard_data()` | 保留 `next_race`（已含会话时间表）；新增 `season` 字段；当 `race_poster_active` 时按"已结束会话"拉取 `qualifying.json` / `sprint.json`，产出 `poster_sessions` 列表 |
| 新增解析函数 | `fmt_qualifying()`（Q3→Q2→Q1 最快圈）、`fmt_sprint()`（Time/status） |
| 新增辅助 | `session_ts(sess)`、`completed_sessions(race, now)`、`weekend_poster_sessions(next_race, season, now)`；每类结果独立容错（失败只空该块） |
| `_draw_poster` | 依据"有无结果"分支：无 → 现版式；有 → 压缩 hero + 渲染结果块堆叠（新 `_draw_poster_results`） |
| `mock_data` | 给 `--mock-race` 增加排位/冲刺赛假数据，便于开发机预览"有结果"版式 |
| `docs/项目说明.md` §7.4 | 同步更新版式说明与数据流 |

请求路径继续用赛季号派生（`season/{round}/qualifying.json`、`season/{round}/sprint.json`），
避免跨赛季窗口 404。标题栏（`ROUND N`）样式不变。

## 7. 边界与风险

- **数据未就绪**：刚过会话开始时间但 API 尚未回结果 → 该块显示 `no data`（局部降级，不拖垮整页）。
- **额外请求**：海报周末态比平时多 1–2 个 GET（qualifying/sprint），仅该周末且仅"已结束会话"才发，
  被约束住；`service` 每 30 分钟 + 唤醒刷新即可覆盖会话结果的自然出现。
- **冲刺排位缺失**：按决策不展示，无近似数据。
- **本地预览**：`png --mock-race --out <path>` 需在 mock 数据中补排位/冲刺结果，
  否则预览不到"有结果"版式。

## 8. 验收标准

1. 普通周末：排位赛结束后，海报在赛道轮廓下方出现 `QUALIFYING` Top5 块。
2. 冲刺周末：冲刺结束后先出现 `SPRINT` 块；排位结束后在其上方追加 `QUALIFYING` 块。
3. 会话未结束时对应块不出现；网络失败时该块 `no data`，其余正常。
4. 无任何会话结束时，海报与 `--mock-race` 现有版式一致（无回归）。
5. `docs/项目说明.md` §7.4 更新到与新版式一致。
