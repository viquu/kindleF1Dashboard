# 屏保视觉升级设计方案 —— "Timing Tower" 编辑风格

> 状态：**提案（已产出预览图，待确认后移植进 `f1dash.py`）**。
> 不改架构、不改数据流、不改刷新机制，只重做两块渲染版式：日常仪表盘 + 赛事周末海报。

## 1. 现状诊断（为什么"没设计感"）

对照 `design/preview/current_*.png`（现行版式基线）：

1. **赛道轮廓被埋没**：全页最有 F1 辨识度的资产缩在右上角一个带边框的小盒子里，像图例而非主角。
2. **所有区块同一视觉语法**：五组内容都是"标题 + 纯文本列表"，无层级对比，读起来像表格文档。
3. **没有对齐系统**：比赛名居中、榜单左对齐、积分右对齐，各自为政，页面上没有一条贯穿的网格线。
4. **构图头重脚轻**：底部约 1/4 完全空白。
5. **海报结果块居中排版**：黑底大版概念成立，但居中列表有"终端输出"感，缺乏版式秩序。

## 2. 设计语言：F1 转播计时塔（Timing Tower）

向 F1 官方转播图形语言借语法，落到 600×800 设计网格（×1.24 → 758×1024 画布）：

| # | 原则 | 具体做法 |
|---|---|---|
| 1 | **赛道轮廓 = 页面主角** | 仪表盘右上 260×204 无边框大图（线宽 4）；海报里保持大号白线主角 |
| 2 | **唯一反色锚点 = 开赛时刻** | 全页只保留两块黑：页眉条 + **开赛时间板**（`LIGHTS OUT · UTC+8` + `DEC 06 · SUNDAY 21:00`）。**不渲染倒计时**：屏保无法实时刷新，`in 85d 07h` 从渲染那一刻起就在失真；"何时比"是永远成立的静态事实 |
| 3 | **计时塔表格语法** | 大写姓氏；名次数字浅灰退后；积分粗黑右对齐；**P1 行加粗**且下方压一条细线；无竖线无斑马纹 |
| 4 | **编辑式小标签** | 区块标题统一为小号大写 + 2~3px 字距（`DRIVER STANDINGS`、`NEXT RACE · ROUND 23`），下压浅灰细线，代替原来的反色标题条 |
| 5 | **灰度纪律** | 五级灰度：`0` 主文字 / `90` 次强调 / `120` 标签 / `170` 细线 / `195` 退后元素；黑底上白 `255` / `210~240` 次级（**上机后按实际观感可整体 +20**，墨水屏抖动会损失中间调） |
| 6 | **圈速尺进度 + 统一页脚** | 赛季进度改为 23 格刻度尺（像圈数计分牌）；两版式共用页眉（赛车剪影 + F1 + 斜纹）与页脚（`LAST UPDATE` · `JOLPICA F1`） |

信息增删（相对现行版式）：

- **保留**：下一场（轮次/日期/北京时间）、双榜 Top 8、上场比赛、赛季进度、海报周末的排位/冲刺渐进赛果。
- **改动**：上场比赛 **Top 5 → Top 3（领奖台）**，为底部腾出呼吸感并强化"领奖台"语义——**此条可否决**，Top 5 空间上仍放得下（行距 26→24）。
- **移除**：一切"相对当前时刻"的动态文案——仪表盘倒计时（`in 85d 07h`）与海报 `RACE LIVE` 字样。理由：零刷新屏保上必然过时失真；海报是否有新赛果，由"结果块是否出现/变长"自然表达。
- **新增**：日期改编辑式写法（`DEC 06`）、海报副标题补举办地（`ZANDVOORT · NETHERLANDS`）、时间板标注时区（`UTC+8`）。

## 3. 版式规格（600×800 设计网格）

### 仪表盘（非赛事周末）

```
0-44     页眉黑条(共用)
66-238   HERO 左文右图: NEXT RACE·ROUND 23(灰标) / ABU DHABI(44px粗) /
         GRAND PRIX(字距灰) ｜ 右侧赛道大图 (312,58)-(572,262)
272-340  开赛时间反色板: LIGHTS OUT · UTC+8(字距小标) +
         DEC 06 · SUNDAY 21:00(34px粗白,fit≤500)
360-381  SEASON 2026 + 23格刻度尺 + 22/23(粗)
408-650  计时塔×2: 左 DRIVER(28-290) 右 CONSTRUCTOR(322-572)
         标签12px → 细线 → 8行×26px,P1粗+细线
660-754  LAST RACE · QATAR: 领奖台 Top3(赢家行加粗)
768-790  页脚细线 + LAST UPDATE / JOLPICA F1
```

### 赛事海报（结果态）

```
0-44     页眉黑条(共用)
56-660   反色海报主体: 赛道白线主角(150,74)-(450,178) →
         DUTCH GRAND PRIX(fit≤36 粗) → ZANDVOORT · NETHERLANDS(字距) →
         SUNDAY 21:00(28px 粗白,开赛时刻为主视觉) →
         QUALIFYING / SPRINT RACE 结果块
         (标签+白细线+5行×28px,P1 行加粗,块间 16px)
692-714  SEASON 2026 · ROUND 12(左) + 刻度尺 + 11/23(右,同一基线)
768-790  页脚(同仪表盘)
```

无赛果态（周末刚开始）：沿用现"大海报"构图（赛道 + 比赛名 + 大倒计时），套用同一字体/灰度/标签语法即可。

边界与守恒：

- 数据流零改动：`get_dashboard_data()` / 刷新时机 / linkss 写图路径全部不动，**纯渲染层替换**。
- 容错不变：FETCH FAILED 仍不覆盖屏保；某区块无数据仍局部降级（计时塔空区显示 `NO DATA` 灰标）。
- `tracks.json` 未收录的赛道：右侧留白，版式仍成立（不画占位框）。
- 姓氏取 `full.split()[-1]`；词数=1 时原样大写。
- 设备端字体 Futura 比预览的 Helvetica 更窄，所有 `fit_size()` 动态缩字逻辑保证不溢出。

## 6. 验收标准

1. `--mock` / `--mock-race` 渲染与 §3 规格一致，无裁切/重叠（预览图已过视觉评审）。
2. 上机后：墨水屏上五级灰度可辨；浅灰元素（名次数字、标签）若过浅，按 §2-5 整体加深一档。
3. 唤醒刷新 / KUAL Refresh Now 显示新版式；正常阅读、屏保休眠流程无回归。
