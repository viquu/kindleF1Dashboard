# Kindle F1 Dashboard 项目说明

用闲置的 Kindle Paperwhite 1 做一块电子墨水 F1 信息牌。

受 [F1 Quote/0](https://sspai.com/post/113158) 项目启发,但完全运行在 Kindle 本机,
无服务端、无 Docker、无外部依赖(仅需联网访问公开 API)。

## 1. 项目简介

- Kindle 正常阅读不受影响,通过 KUAL 菜单进入 F1 功能
- 信息牌模式:设备休眠时,屏保显示 F1 面板(零功耗);唤醒后秒级拉取云端成图,
  配合一键回睡,按一下电源键即可看到最新锁屏
- 临时查看模式:Refresh Now 优先拉云端成图
- 数据源:Jolpica F1 公开 API(免费、无需 Key)

最终形态:

```
+-------------------------+
| F1 DASHBOARD            |
| Next Race               |
| Dutch Grand Prix        |
| Round 12 | 2026-08-23   |
| Driver Standings        |
| 1  Andrea Kimi Antonelli  219
| 2  Lewis Hamilton         169
| ...                     |
| Last update 11:16       |
+-------------------------+
```

## 3. 系统架构

渲染上移 Oracle Cloud(2026-11),Kindle 变纯瘦客户端:只下载成图,云端不可达保留最后一张屏保图,不做本机渲染——

```
        Jolpica F1 公开 API                Oracle Cloud(systemd timer 每 10 分钟)
         (api.jolpi.ca)                    get_dashboard_data() → Pillow → latest.png
                                             |
                                     nginx 静态服务 :8080
                                     http://<host>:8080/f1/latest.png
                                             |
                                     Kindle(唤醒时 pull,~100KB 秒级)
                                             |
                                     linkss 屏保图(拉图失败保留上一张)
                                             |
                                     E-Ink 屏幕(唤醒 + 一键回睡后显示新图)
```

`cloud/render.py` 直接 `import f1dash` 复用取数与渲染,逻辑零分叉;
`cloud/deploy.sh` 一键部署(代码 + venv + 字体 + systemd + nginx + iptables,幂等可重跑)。

`f1dash.py` 四种模式:

| 模式 | 用途 |
|---|---|
| `png` | 拉数据 → Pillow 渲染 758x1024(开发预览;云端 `render.py` 调同一函数) |
| `pull` | 下载云端成图 → 原子替换屏保图(失败保留旧图) |
| `refresh` | 同 `pull`:只下载云端成图,云端不可达保留上一张屏保(不做本机渲染) |
| `service` | 守护进程:唤醒即刷新 + 清醒时每 30 分钟刷新 + 可选一键回睡 |

## 4. 数据源

- **Jolpica F1**(主):原 Ergast API 的继任者,免费无需 Key,格式兼容
  - `https://api.jolpi.ca/ergast/f1/current.json`(赛历)
  - `https://api.jolpi.ca/ergast/f1/current/driverstandings.json`(积分榜)
  - ⚠️ 旧域名 `api.jolpica.com` 已失效(2026 年实测),当前为 `api.jolpi.ca`
- **ESPN 公开接口**(可选,未启用):比赛期间的实时排名数据
- HTTPS 证书:用 Python 包自带的 `certifi` CA bundle
  (`ssl.create_default_context(cafile=certifi.where())`)

## 5. 日常使用

```
信息牌:KUAL → Start Service → Auto Sleep 切到 ON → 按电源键休眠
       → 屏保显示面板;之后按一下电源键,设备自己拉新图并自动回睡,
         锁屏始终显示最新内容(不再需要"解锁再锁屏")
阅读:  KUAL → Auto Sleep 切到 OFF,唤醒后不再自动回睡
临时看:KUAL → Refresh Now(优先拉云端成图,下次休眠显示新图)
停用:  KUAL → Stop Service
```

服务用 `KUAL → Stop Service` 停止;`Enable Wifi` 用于网络断开时手动开启。

## 6. 关键技术点与踩坑记录

全部为在本设备上实测得出的结论,避免重复踩坑。

### 6.1 KUAL 扩展必须带 config.xml 注册

本设备 KUAL(源自 KindleLauncher,版本 18b218e 20250103)通过
`/mnt/us/extensions/<名称>/config.xml` 发现扩展,**只有 menu.json 不显示**。
config.xml 中必须声明菜单文件:

```xml
<menus><menu type="json" dynamic="true">menu.json</menu></menus>
```

新增/修改扩展后,KUAL 检测到变化会提示 "new menu loaded please go to top"
(新菜单在顶部,需向上滚动);或重启 Kindle 使 `/var/tmp/KUAL.cache` 缓存失效。

### 6.2 顶部状态栏归 Kindle 框架所有

Kindle 框架会定时重绘屏幕顶部的系统状态栏(时钟/电量/WiFi),
任何画在该区域的直绘内容都会被覆盖。(屏保模式是整屏图片,无此问题;
这也是本项目不做 FBInk 直绘、只走 linkss 屏保图片的原因之一。)

### 6.3 屏保图片规格(linkss)

- 命名:`bg_ss00.png` 序列,放在 `/mnt/us/linkss/screensavers/`
- 尺寸:758x1024 PNG(KPW1/2),必要时转 8 位灰度;**不能**用改后缀的 jpg
- 显示时**等比缩放**到 600x800 屏幕,无偏移裁剪
- 渲染时内容画在画布中央 600x800 区域(偏移 79,112)即可
- 与 Kindle 原生封面屏保功能冲突(本项目就是要替换它,可接受)
- usbnet 可能影响 linkss,屏保失效时重装 linkss 恢复

### 6.4 RTC 定时唤醒(2026-11-24 重测推翻旧结论)

旧结论(2026-11-24 前):`/sys/class/rtc/rtc1/wakealarm` 写入成功但无法
唤醒挂起中的内核,powerd `rtcWakeup` 不接受外部设置,故放弃休眠中刷新。

重测(2026-11-24 晚,Ken 在家,Zcode)证实旧结论错在两处:
- 旧代码 `rtc.py` 用的是 `/dev/rtc0`(mxc_rtc),其 sysfs 下根本没有
  wakealarm 节点——闹钟机制结构性不存在,找错了 RTC。
- powerd `rtcWakeup` 必须加 `-i` 才能设置(不加 → `0x8
  lipcErrNoSuchProperty`,正是旧结论记录的报错;时机不对 → `0x100`)。

实测 A 路线 `rtc1(pmic_rtc) + echo mem`:120 秒闹钟 118 秒醒 ×3、
600 秒闹钟 598 秒醒,挂起电流约 3mA,醒来直接回 active 且 Wi-Fi 自动
重连。睡眠模式(sleep)即此路线:每小时醒、拉图、刷屏、上报、再睡,
平均约 4–6mAh/h(6–10 天/充)。powerd 路线(B)机制上也通(10+ 次挂起
唤醒无失手),但醒后是 screenSaver 状态、Wi-Fi 不连,且监听器常驻会把
readyToSuspend 倒计时卡在 10,故睡眠模式不用 B 路线。
遥测带睡眠字段(mode/wake_count/last_sleep_s/last_wake_error_s/
sleep_failures);远程 `set_mode sleep/alwayson`(需 confirm=true)切换,
切回常显无需碰设备;万一睡死,按电源键即醒。

### 6.5 其他设备细节

- **入睡命令**:`lipc-set-prop com.lab126.powerd powerButton 1`
  (模拟电源键;从 screenSaver 状态按则唤醒)
- **唤醒检测**:守护进程每 3 秒轮询 `lipc-get-prop com.lab126.powerd state`,
  state → active 即视为唤醒
- **设备没有 nohup**:后台进程用普通 `&` + `</dev/null` 隔离
- **`preventScreenSaver` 是 Int 类型**:传 `1`/`0`,传字符串会报
  `lipcErrNoSuchProperty`(该属性在常亮方案中已弃用)
- **系统字体**(Pillow 渲染用,只读 rootfs 直接引用,无需复制):
  `/usr/java/lib/fonts/Futura-Bold.ttf`、`Futura-Medium.ttf`
- **`ps` 显示限制**:busybox 普通 `ps` 只显示当前会话进程,用 `ps -ef` 查全量
- **Kindle 时区未设置**(按 UTC):脚本里更新时间按北京时间(UTC+8)显示

### 6.6 云端渲染踩坑(Oracle Cloud,2026-11)

- **两层防火墙**:实例内 iptables(`deploy.sh` 自动放行 8080 并
  `netfilter-persistent save` 持久化)之外,还有 **VCN Security List**
  (控制台配置,SSH 改不了)。默认只放行 22,必须手动加 Ingress Rule
  (TCP 8080,0.0.0.0/0),否则公网连接超时
- **测端口连通性要绕开本机代理**:开发机 TUN 代理会把所有出站 TCP
  "乐观接通"(空端口也秒通、失败 5 秒后 reset),探测结果全是假的。
  用另一台干净网络的机器(如 bwg VPS)测才可信
- **字体**:主字体 **Barlow Semi Condensed Bold/Regular**(OFL,已入库
  `cloud/fonts/`,deploy.sh 同步到 `/opt/f1dash/fonts/`),窄体 grotesque
  与计时塔版式气质契合;Futura 副本(`sync_fonts.sh` 可选)与 Jost
  (OFL 可变字体,`set_variation_by_name` 切字重)作后备,`_fit` 动态缩字
  保证任何字体下版式不溢出
- **4× 超采样渲染**:渲染在 3032×4096 画布(`AA_SCALE=4`,fs/fy/字号/线宽
  全链路 ×4)完成后 LANCZOS 缩回 758×1024,线条/文字边缘平滑。设备端已不
  渲染(纯 pull),无算力顾虑;云端实测 CPU ~0.7s、内存 ~32MB、PNG ~72KB
- **渲染代码零分叉**:云端直接 import `kindle/f1dash.py`,改渲染只改一处;
  但 `tracks.json`/`f1logo.json`/`f1icon.json` 是运行时读的数据文件,deploy 必须一起传
  (漏传时赛道轮廓/赛车剪影静默留白,不报错)
- **systemd timer**:`OnCalendar=*:0/10` 每 10 分钟,`Persistent=true`
  补跑错过的触发;主数据失败时 render.py 不覆盖 latest.png 并 exit 1,
  systemd 记录失败但 timer 继续走
- **数据拉取频率与 Jolpica 限速**:每次渲染约 4-5 个 GET,10 分钟一次
  ≈30 req/h,远低于限制;赛事周末想更实时把 timer 的 OnCalendar 改 `*:*`

### 6.7 一键回睡(auto sleep)

- 标志文件 `/mnt/us/f1dash/auto_sleep` 存在时,守护进程在"唤醒触发的刷新成功"
  后发 `lipc-set-prop com.lab126.powerd powerButton 1` 模拟电源键入睡
  (该命令是双刃:screenSaver 态是唤醒、清醒态是入睡,见 §6.5)
- 只在唤醒转换时回睡;启动 service 时的首次刷新与清醒中的周期刷新不回睡
  (避免抢走正在使用的设备);刷新失败(断网)不回睡,留给用户处理
- KUAL 菜单标签由 `autosleep_toggle.sh` 改写 menu.json 同步状态
  (config.xml `dynamic="true"`,KUAL 检测到菜单文件变化会重载;
  若未重载,状态以标志文件为准)

### 6.8 开发原则

- 不修改 rootfs(`mntroot rw` 不要执行),所有文件放 `/mnt/us/`
- 不要让 F1 程序永久占用 Kindle:临时查看执行一次即退出;
  信息牌模式通过屏保实现,阅读功能完全不受影响

### 7.1 数据流与布局(2026-08 内容扩展版)

每次刷新 4 个 GET(赛历 + 车手榜 + 车队榜 + 上场比赛结果),赛历是唯一主获取
(失败则本次不出图,云端保留上一张成功图),其余三块各自容错(失败只空对应区块)。

单页紧凑两栏布局(以 600×800 设计网格为准,渲染时经 `FULL_SCALE` 等比放大到整张
758×1024 画布,`fs()/fy()/fbox()` 完成坐标映射,只留极细边距):

| 区块 | 位置 | 内容 |
|---|---|---|
| 页眉黑条 | y 0-44 | 白色头盔图标 + F1 DASHBOARD(反色居中)+ F1 官方徽标(右上,2017 版飞旗标) |
| HERO | y 66-262 | 左:NEXT RACE·ROUND 标签 + 比赛名大字(`_fit` 缩字)+ GRAND PRIX 字距副标;右:赛道轮廓主角(无边框) |
| 开赛时刻板 | y 272-340 | 全页唯一反色锚点:LIGHTS OUT · UTC+8 + `DEC 06 · SUNDAY 21:00`(北京时间,不渲染倒计时) |
| 赛季进度 | y 352-373 | SEASON 标签 + 23 格刻度尺 + `20/23`(右对齐) |
| 双计时塔 | y 388-650 | 车手/车队各 **10 行 × 24px**,P1 加粗压细线,第 2 名起灰字标落后差距(`_leader_gap`) |
| 上场比赛 | y 664-752 | 领奖台 Top 3 × 22px,胜者行加粗 |
| 页脚 | y 768 | 细线 + LAST UPDATE(北京时间) |

关键实现点:
- `race_start_ts()` 统一 date+time → epoch(UTC),上一场判定/进度复用;
  time 为 "TBD" 时返回 None
- 榜单 points 是字符串;落后差距列经 `float` 解析计算(`_leader_gap`),
  差距列右缘按积分实宽左移(`textlength`),窄体下不与车手名碰撞
- `find_last_race()` 按"开始时间 < now"判定,赛季结束返回最后一轮、休赛期返回 None
  (休赛期上场比赛回退上一赛季 `(season-1)/last/results.json`)
- 请求路径用赛季号派生(如 `2026/driverstandings.json`)而非 `current`,
  避免 1 月跨赛季窗口 404
- `draw_track()` 坐标必须加画布偏移 DX/DY(踩坑:漏偏移会把赛道画到画布角落;
  v2 改为 `DX=DY=0`,坐标经 `fs()/fy()/fbox()` 映射,赛道/文字随 `FULL_SCALE` 放大铺满全屏)
- tracks.json 模块级缓存,每轮刷新不重复读盘;赛道未收录时该区块留白

### 7.2 赛道数据(F1DB)

- 来源:github.com/f1db/f1db `src/assets/circuits/black-outline/`,Jules Roy,CC BY 4.0
- SVG 是单 `<path>` 轮廓,含 M/c/h/l/a 等完整命令集;每条赛道多版本
  (如 `zandvoort-1` ~ `zandvoort-5`),取版本号最大(最新布局)
- `tools/make_tracks.py` 解析 path → 贝塞尔采样 → 抽稀(≈100-170 点/条)
  → 0-1000 整数网格(保纵横比)→ tracks.json(~26KB)
- 生成时用 contact sheet 拼图 + IoU(0.79-0.90)双重验证形态保真
- 新赛道出现时:重新跑 `make_tracks.py` 并在 CIRCUITS 映射表补充
- 注意 `z` 命令必须把终点闭合回起点,否则赛道轮廓断开

### 7.3 页眉头盔图标(Material Design Icons)

- 来源:MDI `racing-helmet`(Pictogrammers,**Apache 2.0**,经 Iconify 直链获取),
  `tools/make_icon.py` 下载解析 → `kindle/f1icon.json`(rings 与 tracks.json 同规格)
- **为什么放弃车辆剪影**:game-icons 剪影(初版)卡通感强,项目自绘的现代 F1
  侧视(二版)在 44px 高的页眉里比例/细节糊成一团——具象车辆剪影细节密度
  超过小尺寸可读上限;头盔是单个大块面形状 + 一个面甲缺口,任何尺寸都清晰
- 渲染:与官方徽标共用 `draw_mark()`(逐环 polygon 填充,union bbox 等比装 box),
  页眉 box x14-66/y8-38,白色(fill=255)反色,面甲开口朝右(朝向版面文字)
- 图标选型过程:iconify.design 聚合 200+ 专业开源图标集(Phosphor/MDI/Solar 等),
  方格旗/头盔/秒表/速度表均有多套现成实现,--sheet 拼图对比后选定 MDI 头盔

### 7.4 F1 官方徽标(Wikimedia Commons)

- 来源:commons.wikimedia.org `File:Formula One logo.svg`(2017 版飞旗徽标,
  F 上翼 + 下翼 + "1" 块三个实心形状;Commons 标记 **Public domain**)。
  F1 徽标是 Formula One Group 的注册商标,仅个人非商用屏保显示
- 生成:`tools/make_logo.py` → `kindle/f1logo.json`,结构与 f1icon.json 同构
  (`rings` 数组),渲染直接复用 `draw_mark()`;白色缝隙是形状间留白而非挖孔
- **踩坑:多形状资产必须全环 union 归一化**——make_tracks 的 `normalize()`
  是单环 bbox 归一化,逐环调用会把每个形状各自拉伸满格、相对位置全毁,
  三形状粘连成斜带(评审逮出);`normalize_group()` 用 union bbox 共享缩放
- ® 字标环簇(外圈/内圈/R 三个小环)按面积过滤剔除(≥最大环面积 25%),
  页眉 20px 高度下它会糊成墨点
- 页眉位置:fbox(498, 11, 578, 34),4:1 徽标按高约束装满,右缘与旧字标对齐

### 7.4 赛事海报(赛事周末版式,2026-08 新增)

距下一场开赛 **<3 天**(含比赛进行中)时,屏保从信息密集的仪表盘切换为"赛事海报"
反色版式,突出赛事氛围;赛程剩余 >3 天自动回到仪表盘。

海报有两种状态,由"本周末哪些赛果会话已结束"自动切换:

**状态 A —— 无赛果(周末刚开始)**:主赛道轮廓 + 比赛名 + 地点 + 开赛时刻 + 超大空心轮次数字。

| 区域 | 位置 | 内容 |
|---|---|---|
| 页眉黑条 | y 0-44 | 同仪表盘(赛车剪影 + F1 DASHBOARD + 官方徽标) |
| 海报面板 | y 56-664 | 反色黑底:大号赛道轮廓(白线 96-300)→ 比赛名(340,`_fit` 缩字)→ 地点·国家(382,字距)→ 开赛时刻(430,记分牌式大字)→ **ROUND 小标签(490)+ 超大空心轮次数字(白描边黑填充,占面板下半)** |
| 赛季进度 | y 694-701 | SEASON · ROUND(左)+ 刻度尺 + N/23(右) |
| 页脚 | y 768 | Last update |

**状态 B —— 有赛果(排位/冲刺赛已结束)**:压缩 hero + 结果块堆叠,海报更"有用"。

| 区域 | 位置 | 内容 |
|---|---|---|
| 页眉黑条 | y 0-44 | 同状态 A |
| 海报面板 | y 56-660 | 赛道轮廓(白线 74-178)→ 比赛名(188)→ 地点·国家(226)→ 开赛时刻(250)→ 结果块堆叠(**排位赛**在前、**冲刺赛**在后;标签 + 白细线 + Top 5,P1 行加粗) |
| 赛季进度 + 页脚 | y 694/768 | 同状态 A |

关键实现点:
- `race_poster_active()`:判 `下一场开赛时间 - now <= RACE_POSTER_WINDOW`(3 天);
  开赛后(`find_next_race` 在开赛 2 小时内仍视为当前)海报继续展示
- **超大空心数字**:`text()` 闭包透传 Pillow `stroke_width/stroke_fill`
  (`stroke_width=lw(3)`,填充面板黑、白色描边);垂直节奏 SUNDAY→标签→数字
  约 23/22 画布px(两间隙均分是几何上限)、数字底距面板缘 ~46;仅状态 A 有
  (状态 B 面板被结果块占满)
- **会话时间表直接读 `next_race`**(`current.json` 已带 `Qualifying`/`Sprint`,UTC):
  `completed_sessions()` 按 `session_ts() <= now` 判定"该会话已结束";
  `weekend_poster_sessions()` 仅拉取已结束会话的数据(避免白请求)。
- **数据源**:排位赛结果 `season/{round}/qualifying.json`(每站都有);冲刺赛结果
  `season/{round}/sprint.json`(仅冲刺站)。⚠️ **Jolpica 无独立的冲刺赛排位赛结果端点**
  (`/sprintqualifying.json` 返回 400),故冲刺周末海报只展示**冲刺赛结果 + 排位赛结果**,
  不展示冲刺排位赛(按需求决策)。
- 每个结果块独立容错:某接口失败只空该块(`no data`),不影响整页。
- `format_race_daytime()`:比赛日按北京时间(UTC+8)显示,如 "SUNDAY 21:00"
- `draw_track_fit()`:赛道轮廓按实际 bbox 等比装入 box(而非按满格 1000 网格),
  避开 Zandvoort 等赛道自身的纵横比留白,让轮廓成为海报主角
- `_fit()`:赛道名/开赛时刻自动缩小字号直到宽度 ≤ 上限,长赛道名(如
  "United States Grand Prix")也不溢出
- 主数据源失败时云端 `render.py` 不出图、不覆盖上一张 latest.png(exit 1 交给 systemd 记失败)
- 开发机预览:`png --mock-race --out <path>`(进赛事窗口海报版式,含排位/冲刺结果块)、
  `png --mock`(远期收官战,仪表盘版式)
