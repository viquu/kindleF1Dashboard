# Kindle F1 Dashboard 项目说明

用闲置的 Kindle Paperwhite 1 做一块电子墨水 F1 信息牌。

受 [F1 Quote/0](https://sspai.com/post/113158) 项目启发,但完全运行在 Kindle 本机,
无服务端、无 Docker、无外部依赖(仅需联网访问公开 API)。

## 1. 项目简介

- Kindle 正常阅读不受影响,通过 KUAL 菜单进入 F1 功能
- 信息牌模式:设备休眠时,屏保显示 F1 面板(零功耗),唤醒后 2 秒内自动刷新
- 临时查看模式:Refresh Now 直接在屏幕显示
- 数据源:Jolpica F1 公开 API(免费、无需 Key)

最终形态:

```
+-------------------------+
| F1 DASHBOARD            |
| Next Race               |
| Dutch Grand Prix        |
| Round 12 | 2026-08-23   |
| Driver Standings        |
| 1  Andrea Kimi Antonelli  219
| 2  Lewis Hamilton         169
| ...                     |
| Last update 11:16       |
+-------------------------+
```

## 3. 系统架构

无中间服务器,Kindle 直连公开 API:

```
             Jolpica F1 公开 API
              (api.jolpi.ca, HTTPS JSON)
                      |
              Kindle Python 3.9(内置 SSL)
                      |
             +--------+--------+
             |                 |
          Pillow             FBInk
      (屏保 PNG 渲染)     (临时直显)
             |                 |
             +--------+--------+
                      |
                E-Ink 屏幕
```

`f1dash.py` 三种模式:

| 模式 | 用途 |
|---|---|
| `show` | 拉数据 → FBInk 文本直显(临时查看) |
| `png` | 拉数据 → Pillow 渲染 758x1024 → 写 linkss 屏保图 |
| `service` | 守护进程:唤醒即刷新 + 清醒时每 30 分钟刷新 |

## 4. 数据源

- **Jolpica F1**(主):原 Ergast API 的继任者,免费无需 Key,格式兼容
  - `https://api.jolpi.ca/ergast/f1/current.json`(赛历)
  - `https://api.jolpi.ca/ergast/f1/current/driverstandings.json`(积分榜)
  - ⚠️ 旧域名 `api.jolpica.com` 已失效(2026 年实测),当前为 `api.jolpi.ca`
- **ESPN 公开接口**(可选,未启用):比赛期间的实时排名数据
- HTTPS 证书:用 Python 包自带的 `certifi` CA bundle
  (`ssl.create_default_context(cafile=certifi.where())`)

## 5. 日常使用

```
信息牌:KUAL → Start Service → 按电源键休眠
       → 屏保显示面板;唤醒后 2 秒内自动刷新,再入睡即可
临时看:KUAL → Refresh Now → 屏幕直接显示 → Home 退出
停用:  KUAL → Stop Service
```

服务用 `KUAL → Stop Service` 停止;`Enable Wifi` 用于网络断开时手动开启。

## 6. 关键技术点与踩坑记录

全部为在本设备上实测得出的结论,避免重复踩坑。

### 6.1 KUAL 扩展必须带 config.xml 注册

本设备 KUAL(源自 KindleLauncher,版本 18b218e 20250103)通过
`/mnt/us/extensions/<名称>/config.xml` 发现扩展,**只有 menu.json 不显示**。
config.xml 中必须声明菜单文件:

```xml
<menus><menu type="json" dynamic="true">menu.json</menu></menus>
```

新增/修改扩展后,KUAL 检测到变化会提示 "new menu loaded please go to top"
(新菜单在顶部,需向上滚动);或重启 Kindle 使 `/var/tmp/KUAL.cache` 缓存失效。

### 6.2 顶部状态栏归 Kindle 框架所有

Kindle 框架会定时重绘屏幕顶部的系统状态栏(时钟/电量/WiFi),
任何画在该区域的 FBInk 内容都会被覆盖。**内容一律从第 4 行(64px)开始**。
(屏保模式下无此问题,因为屏保是整屏图片。)

### 6.3 屏保图片规格(linkss)

- 命名:`bg_ss00.png` 序列,放在 `/mnt/us/linkss/screensavers/`
- 尺寸:758x1024 PNG(KPW1/2),必要时转 8 位灰度;**不能**用改后缀的 jpg
- 显示时**等比缩放**到 600x800 屏幕,无偏移裁剪
- 渲染时内容画在画布中央 600x800 区域(偏移 79,112)即可
- 与 Kindle 原生封面屏保功能冲突(本项目就是要替换它,可接受)
- usbnet 可能影响 linkss,屏保失效时重装 linkss 恢复

### 6.4 RTC 定时唤醒不可行(重要结论)

曾计划"休眠中定时唤醒刷新",实测此设备不可行:

- `/sys/class/rtc/rtc1/wakealarm` 写入成功、闹钟会触发,但**无法唤醒挂起中的内核**
- powerd 的 `rtcWakeup` 属性不接受外部设置(`lipcErrNoSuchProperty`)
- 因此放弃休眠中刷新,改用**唤醒即刷新**:设备休眠时守护进程冻结,
  唤醒后 3 秒内重新渲染屏保图。F1 数据变化不频繁,完全够用

### 6.5 其他设备细节

- **入睡命令**:`lipc-set-prop com.lab126.powerd powerButton 1`
  (模拟电源键;从 screenSaver 状态按则唤醒)
- **唤醒检测**:守护进程每 3 秒轮询 `lipc-get-prop com.lab126.powerd state`,
  state → active 即视为唤醒
- **设备没有 nohup**:后台进程用普通 `&` + `</dev/null` 隔离
- **`preventScreenSaver` 是 Int 类型**:传 `1`/`0`,传字符串会报
  `lipcErrNoSuchProperty`(该属性在常亮方案中已弃用)
- **系统字体**(Pillow 渲染用,只读 rootfs 直接引用,无需复制):
  `/usr/java/lib/fonts/Futura-Bold.ttf`、`Futura-Medium.ttf`
- **`ps` 显示限制**:busybox 普通 `ps` 只显示当前会话进程,用 `ps -ef` 查全量
- **Kindle 时区未设置**(按 UTC):脚本里更新时间按北京时间(UTC+8)显示

### 6.6 开发原则

- 不修改 rootfs(`mntroot rw` 不要执行),所有文件放 `/mnt/us/`
- 不要让 F1 程序永久占用 Kindle:临时查看执行一次即退出;
  信息牌模式通过屏保实现,阅读功能完全不受影响

### 7.1 数据流与布局(2026-08 内容扩展版)

每次刷新 4 个 GET(赛历 + 车手榜 + 车队榜 + 上场比赛结果),赛历是唯一主获取
(失败整页 FETCH FAILED),其余三块各自容错(失败只空对应区块)。

单页紧凑两栏布局(600×800 设计区,画布偏移 79,112):

| 区块 | 位置 | 内容 |
|---|---|---|
| 标题栏 | y 0-56 | 左侧白色赛车剪影(x8-158);居中 DASHBOARD(反色);右侧 x452-580 "F1" 字标(rm 锚点)+ 3 条白色斜纹 |
| NEXT RACE | y 64-196 | 赛道名/轮次日期/倒计时(`in 7d 06h`);右侧 460-590 赛道轮廓图框 |
| 赛季进度 | y 184-190 | 进度条 x20-320 + `11/23`(右对齐 x460) |
| 两栏榜单 | y 246-510 | 车手/车队各 8 行 × 30px |
| 上场比赛 | y 496-682 | Top 5 × 32px,胜者总时长/差距,退赛者 status |
| 页脚 | y 760 | Last update |

关键实现点:
- `race_start_ts()` 统一 date+time → epoch(UTC),倒计时/上一场判定/进度复用;
  time 为 "TBD" 时返回 None,倒计时不显示
- 榜单 points 是字符串,显示前必须 `int()` 归一化
- `find_last_race()` 按"开始时间 < now"判定,赛季结束返回最后一轮、休赛期返回 None
  (休赛期上场比赛回退上一赛季 `(season-1)/last/results.json`)
- 请求路径用赛季号派生(如 `2026/driverstandings.json`)而非 `current`,
  避免 1 月跨赛季窗口 404
- `draw_track()` 坐标必须加画布偏移 DX/DY(踩坑:漏偏移会把赛道画到画布角落)
- tracks.json 模块级缓存,每轮刷新不重复读盘;赛道未收录时该区块留白

### 7.2 赛道数据(F1DB)

- 来源:github.com/f1db/f1db `src/assets/circuits/black-outline/`,Jules Roy,CC BY 4.0
- SVG 是单 `<path>` 轮廓,含 M/c/h/l/a 等完整命令集;每条赛道多版本
  (如 `zandvoort-1` ~ `zandvoort-5`),取版本号最大(最新布局)
- `tools/make_tracks.py` 解析 path → 贝塞尔采样 → 抽稀(≈100-170 点/条)
  → 0-1000 整数网格(保纵横比)→ tracks.json(~26KB)
- 生成时用 contact sheet 拼图 + IoU(0.79-0.90)双重验证形态保真
- 新赛道出现时:重新跑 `make_tracks.py` 并在 CIRCUITS 映射表补充
- 注意 `z` 命令必须把终点闭合回起点,否则赛道轮廓断开

### 7.3 赛车剪影数据(game-icons.net)

- 来源:commons.wikimedia.org `File:F1-car_-_game-icons.svg`,Skoll(game-icons.net),CC BY 3.0
- 与赛道同款方案:SVG path → 0-1000 整数网格坐标,产物 `kindle/car.json`:
  `{"_source": ..., "rings": [闭合环, ...]}`,**rings 为闭合环数组**(车身带轮拱负空间 1 环 + 前后轮各 1 环)
- `tools/make_tracks.py` 的 `parse_svg_paths()`(新函数,旧 `parse_svg_path` 未动):
  子路径拆分(M/m 开新环)+ **A/a 圆弧按 F.6.5 端点→圆心参数化采样约 24 点**——
  旧函数把圆弧近似为直线,整圆轮子会退化成零面积,因此必须单独实现
- 设备端 `draw_car(fill=…)`:按 rings 实际 bbox 等比装入 box;逐环 polygon 填充——
  Pillow 填充规则在嵌套子路径下会把轮子与车身重叠区挖成孔,分开填同色天然合并
- 剪影纵横比约 3.75:1(1000×267);标题栏左侧 box x8-158/y10-46,白色(`fill=255`)反色,
  车头朝左(网格 x=0 为车头)
- 生成/核对:`tools/make_car.py`(下载需带 User-Agent,Wikimedia 拒无 UA 请求)→
  `--sheet` 生成 car_sheet.png 拼图人工核对
- 标题栏字标为白色 "F1" 字(rm 锚定 x575 不右溢)+ 3 条 2px 白色斜纹;
  未做仿射斜切(e-ink 灰度下重采样糊灰点,设备 Futura 无斜体字形)
